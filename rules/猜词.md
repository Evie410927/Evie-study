# 猜词场景规则

当用户输入中含有关键字“猜词”时，表示用户从韩剧、综艺、现实对话或其他音频中听到了韩语，但不能确定原文拼写，希望根据**近似发音、中文意思和上下文**反推说话者最可能说的韩语单词、活用形式、短语或整句表达。

所有分析、判断依据和不确定性说明一律使用中文。韩文仅用于候选词条、还原表达和例句。

## 核心原则

1. **必须先推测，不得因信息不完整就只向用户追问。** 应先利用现有线索给出最合理候选；只有确实存在多个接近答案时，才在答案末尾询问一句最有区分度的上下文问题。
2. **发音和语义必须同时匹配。** 不得只因中文意思接近就忽略用户听到的音，也不得只因读音相似就推荐语义或使用场景明显不符的词。
3. **优先考虑韩国人真实口语。** 必须综合日常使用频率、韩剧常见说法、语气、敬语等级、固定搭配、句尾、吞音、连音、鼻音化、流音化、紧音化、激音化以及口语缩约进行判断。
4. **听到的内容不一定是字典原形。** 必须检查它是否是动词或形容词的活用形、名词加助词、否定结构、惯用表达、句型片段或多个词连读，并还原完整表达及字典原形。
5. **严禁把猜测冒充定论。** 除非发音、语义和语境高度唯一，否则必须明确标注置信度，并说明仍可能存在的歧义。
6. **候选必须真实存在且自然。** 对不熟悉、生僻或把握不足的候选，应先通过 Naver 词典、韩国语基础词典或韩国真实语料核验，不得拼凑不存在的韩语词。

## 推测步骤

必须按以下线索综合排序，不可只看其中一项：

1. 用户描述的中文意思或该句在剧情中的实际作用；
2. 用户听到的近似音节，包括用中文、拼音、罗马字或不确定韩文记录的声音；
3. 前后句、人物关系、说话语气、动作、情绪和场景；
4. 标准发音发生音变后与用户听感的接近程度；
5. 口语连读、缩略、吞音后与用户听感的接近程度；
6. 候选在韩国日常对话及韩剧中的自然度和使用频率。

如用户提供的是整段近似音，应主动尝试切分音节，判断它可能由哪些词、助词、词尾或固定句型组成，不得强行把整段声音当成一个单词。

## 候选数量与排序

- 默认给出最可能的 1～3 个候选；只有确有必要时才扩展到 5 个。
- 候选必须按可能性从高到低排列。
- 第一候选必须是综合“发音、中文意思、语境、口语频率”后最合理的答案，不得机械按字典释义排序。
- 如果第一候选明显领先，应直接说明“最可能是”。如果证据接近，应说明“目前无法唯一确定”。

## 每个候选的必备信息

每个候选必须包含：

1. 韩语原话或最可能出现的实际活用形式；
2. 字典原形；若实际说法本身就是原形，可合并说明；
3. 词性及准确中文意思；
4. 标准实际读音，必须使用韩文方括号标注，并反映真实音变；
5. 置信度：高 / 中 / 低；
6. 发音对应说明：具体解释用户听到的声音如何对应到该韩语表达；
7. 语境依据：说明它为什么符合用户给出的中文意思和韩剧场景；
8. 若不是第一候选，必须说明它与第一候选相比不够吻合的地方。

## 回复格式

所有需要分行的信息末尾必须显式添加 `<br>`，防止 Markdown 将内容合并。推荐格式：

```text
最可能是：**[实际说法]**<br>
原形：**[字典原形]**<br>
（[词性]）[中文意思]<br>
实际读音：[韩文实际读音]<br>
置信度：[高 / 中 / 低]<br>
发音对应：[用中文解释近似音、音变、连读或缩约]<br>
语境依据：[用中文解释为什么符合剧情和意思]
```

存在其他合理答案时，再按“候选 2”“候选 3”依次使用相同结构列出。不同候选之间使用标准 Markdown 空行分隔，绝对禁止使用隐形占位字符。

## 证据不足时的处理

- 即使线索不足，也要先给出当前最合理候选和置信度，不得只回复“请提供更多信息”。
- 答案末尾最多询问一个最能缩小范围的问题，例如：前后还听到了什么音、人物当时在做什么、这句话是敬语还是平语。
- 不要要求用户必须提供剧名、集数或时间点；这些信息只有在确实有助于核实时才作为可选补充。
- 如果所有候选都很弱，必须直说“目前只能低置信度推测”，不得硬选一个答案。

## 与其他场景的联动

- 用户只写“猜词”时，只执行推测，不得自动加入单词本。
- 即使同一条输入还包含“单词本”“note”“노트”或“ノート”，也必须先完成猜词并让用户确认准确词条；在用户确认之前，绝对不得把任何候选加入单词本。
- 用户确认某一候选后，如继续要求“解释”“区别”或“表达”，再读取并遵守对应规则。
- 用户确认候选并明确触发加入单词本时，才按照项目的加词校验、防重复、读音、例句和部署规则执行。
