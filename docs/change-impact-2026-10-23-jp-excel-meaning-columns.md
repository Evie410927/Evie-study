# JP Excel 中韩释义拆列变更影响

## 问题与完成标准

- 问题：JP Excel 把中文释义与韩文释义合并在同一单元格，不能独立编辑、筛选和回导。
- 用户可观察结果：JP 导出与列选择器分别显示“中文释义”“韩文释义”，默认均勾选；回导时分别覆盖编辑弹窗中的两个字段。
- 明确不在范围内：不改变 KR 表格列，不改变词库字段、云端表结构、例句或相近词格式。
- 完成标准：JP 新工作簿两列内容独立；任一列可单独导出和导入；表头改名仍整体拒绝；版本历史与失败回滚保持有效。

## 影响范围

- [x] KR 应用（保持镜像实现并验证 KR 不显示 JP 专属列）
- [x] JP 应用
- [x] 数据字段或缓存迁移（无迁移，仅既有 `krMeaning` 映射）
- [ ] localStorage / IndexedDB
- [ ] 云端 payload / RLS / 版本协议
- [ ] 列表 / 详情 / 复习 / 相近表达
- [x] 移动端与空状态
- [x] 现有规则或 ADR

## 风险与回滚

- 数据兼容风险：旧版“中韩意思”合并表头不再属于当前严格回导格式，避免无法判断换行属于中文还是韩文。
- 并发或跨设备风险：无新增风险；导入差异继续进入逐字段待上传队列。
- 安全与隐私风险：无新增风险；隐藏稳定 ID 和本地解析边界不变。
- 回滚方法：回退本次提交；已导出的新文件不会改写词库，已导入内容可从云朵入口的版本历史恢复。

## 验证计划

- 新增或更新的测试：验证 JP 默认五列、两列独立内容与独立回导；验证 KR 仍为默认四列且不显示韩文释义列；验证严格表头和导入回滚回归。
- 必须运行的质量门禁：`python scripts/run_quality_gate.py`
- 部署后验证：KR/JP 在线页均包含语言条件列逻辑，JP 导出 XML 同时包含“中文释义”和“韩文释义”。
