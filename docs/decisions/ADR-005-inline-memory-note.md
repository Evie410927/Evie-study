# ADR-005：列表卡片原位维护独立发音备注

- 状态：Accepted
- 日期：2026-09-29

## 背景

词条已有 `userNote` 自定义说明字段，用于卡片下方 `【…】` 单词内容解释。用户还需要在红色读音旁单独记录发音或容易混淆时的个人记忆方式；这不是内容说明，生命周期必须完全独立。

## 决策

1. 新增独立字段 `pronunciationNote` 存放标题行发音/记忆提示；`userNote` 只存放下方中括号内容说明。两字段不得互相回填、覆盖、清空或迁移。
2. 列表卡片在红色读音之后紧邻显示约 15px 的弱化圆形 `＋`；点击后直接在标题同一排展开紧凑单行输入框，不使用 `prompt` 或额外弹窗。
3. 点击 `＋` 打开的输入框必须完全空白且不显示 placeholder，非空新内容追加到 `pronunciationNote`；点击已有发音备注文字时，同一输入框回填当前完整内容，保存后以编辑结果替换旧值。
4. 两种模式均按 Enter 或失焦保存、按 Escape 取消；空内容失焦不得清除旧值，删除仍只由明确的 `×` 操作完成。
5. 非空 `pronunciationNote` 在标题行紧邻入口显示，并在末尾提供小型 `×` 直接删除；`userNote` 继续使用原有中括号样式，不因本功能新增行内删除入口。
6. `＋`、输入框与 `×` 均阻断卡片详情点击，不能误开详情或触发其他操作。
7. 新增、修改和删除统一更新时间、用户编辑时间与 `pronunciationNote` 字段时间，复用现有 localStorage、IndexedDB、导入导出和云同步待上传机制；保存失败不显示成功。
8. 详情、复习、相近表达及完整编辑弹窗中的内容说明继续只读或编辑 `userNote`，不展示或改写 `pronunciationNote`。

## 验证

- 静态测试校验字段隔离、控件位置、`＋` 空白追加、已有文字回填替换、500 字符总长度约束、事件隔离和持久化调用。
- Selenium 在 KR/JP 两端预置不同的 `userNote` 与 `pronunciationNote`，实际执行点击 `＋` 追加、点击已有备注回填修改、刷新重绘、点击 `×` 删除，并确认内容说明始终不变以及云同步只追踪 `pronunciationNote`。
- 执行完整质量门禁并核验 GitHub Pages 双端部署内容。
