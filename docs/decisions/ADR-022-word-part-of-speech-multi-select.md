# ADR-022：词条词性多选与兼容表示

- 状态：Accepted
- 日期：2026-11-12

## 背景

完整新增/编辑词条弹窗原先只能选择一个词性，但同一词条可能同时承担动词、名词、短语等多个语法角色。只改下拉交互会导致筛选、卡片展示、Excel 回导和云同步无法理解多个值。

## 决策

1. `partOfSpeech` 继续使用现有字符串字段，保持 localStorage、IndexedDB、Supabase payload、HTML/JSON 与 Excel 的向后兼容；多个词性按用户顺序去重后以全角顿号 `、` 连接，例如 `动词、短语`。
2. 读取时同时接受单值、`、`、中英文逗号、分号和换行分隔的旧值或外部输入；规范化保存和 Excel 导出时统一写成 `、` 分隔字符串。不得拆分斜杠等可能属于自定义词性名称的字符。
3. 新增/编辑弹窗的候选列表改为多选：点击候选项切换选中状态、显示勾选并保持列表展开；再次点击取消。输入框继续允许自定义词性及多值输入，至少保留一个词性才允许保存。
4. 列表、详情、复习背面与相近表达为每个词性分别渲染独立 Badge；自定义 Tag 不得重复包含任一词性。
5. 列表词性筛选与自由复习词性筛选按单个词性展开候选；一个词条只要包含所选任一词性即命中。计数按包含关系计算，每个词条在单个词性下只计一次。
6. Excel 的“词性”单元格使用规范的 `、` 分隔文本；严格回导解析多个词性并整体覆盖该词条的词性集合，继续遵守现有快照、回滚与逐字段同步规则。
7. KR/JP 使用完全相同的 DOM、样式、解析、保存、筛选、导入导出和测试逻辑。

## 兼容与同步

- 单值旧词条无需迁移即可继续使用，首次编辑或相关导入时才按统一格式重写。
- 云端仍以 `partOfSpeech` 单字段逐字段合并，不新增表列，不改变冲突时间戳协议。
- 若旧客户端读取多值字符串，会把整段显示为一个词性文本，但不会丢失内容；新客户端会正确拆分展示和筛选。

## 验证

- 静态检查多值解析、候选切换、独立 Badge、筛选包含关系、Excel 规范化和双端镜像。
- 浏览器测试验证新增/编辑时选择两个词性、取消其中一个、首次点击保存、重开回填、列表/详情展示及词性筛选。
- 完整运行 `python scripts/run_quality_gate.py`。
