# ADR-004：相近表达按源词条独立持久化自定义顺序

- 状态：Accepted
- 日期：2026-09-29

## 背景

相近表达关系是双向的，但用户在不同词条中关注的先后顺序可能不同。详情弹窗、复习背面以及新增/编辑词条弹窗中的已选相近词都需要直接调整优先级。

## 决策

1. `manualSimilarWordIds` 的数组顺序同时作为当前源词条的相近表达展示顺序。
2. 详情弹窗与复习背面使用同一顺序，并允许直接拖动整张相近表达卡片排序；新增/编辑词条弹窗中的已选相近词卡片同样支持整卡拖动。
3. 不增加拖拽按钮或手柄；鼠标可直接拖动，触屏长按卡片后拖动，短按仍打开词条详情。
4. 卡片内的删除、掌握状态和星级控件不触发拖拽。
5. 详情与复习中的排序只更新当前源词条的数组顺序。双向关系仍然保留，但反向词条拥有独立顺序。
6. 详情与复习排序成功后更新用户编辑时间、持久化到本地并进入现有云同步待上传机制。
7. 新增/编辑词条弹窗中的排序只更新 `editingModalSimilarWordIds` 草稿，不得立即改写正式词条、localStorage、IndexedDB 或云同步队列；点击保存词条时沿用现有表单保存事务一次性写入，关闭弹窗则放弃该顺序。
8. 编辑弹窗、详情和复习共用拖动状态与触屏长按阈值；编辑弹窗滚动时应以当前 `.modal-sheet` 为自动滚动容器，删除按钮仍不得触发拖动。

## 验证

- 静态测试确认三处整卡拖拽事件、无额外拖拽控件、正式顺序持久化、编辑草稿延迟保存与交互控件隔离。
- Selenium 分别在详情、复习和新增/编辑词条弹窗执行排序，验证详情与复习即时同步持久化；编辑弹窗拖动时正式数据保持不变，保存后才按草稿顺序写入且反向词条顺序不变。
- KR 与 JP 两端执行完全相同的断言和完整质量门禁。
