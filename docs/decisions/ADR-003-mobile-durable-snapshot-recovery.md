# ADR-003：启动时恢复最新的有效本地快照

- 状态：Accepted
- 日期：2026-09-28

## 背景

移动浏览器可能因 localStorage 容量或权限限制，无法覆盖较大的最新词库，却仍保留一份较小的旧词库。云同步下载可以成功写入 IndexedDB，但如果重开页面时只判断 localStorage 是否为空，旧的非空数据会阻止 IndexedDB 恢复，造成词条数量回退。

## 决策

localStorage 继续作为同步读取的主存储，IndexedDB 作为耐久备用层。每次 IndexedDB 快照成功落盘时，仅在 localStorage 中的词库内容与该快照完全一致时，写入带内容指纹的轻量快照元数据。

页面启动时必须读取两层候选数据，并按以下顺序判断：

1. 有效内容指纹对应的快照保存时间；
2. 在本地主存储没有有效保存时间时，先检查已排除删除墓碑的词条集合差异；如果 IndexedDB 是 localStorage 的严格超集且不存在本地独有词条，优先恢复 IndexedDB；
3. 云端基线版本；
4. 词条、字段、待同步项及删除墓碑的最大变更时间；
5. 其他已排除删除墓碑的词条集合差异。

只有 IndexedDB 候选明确更新时才恢复，避免旧备用快照覆盖更新的本地编辑。localStorage 非空本身不再是跳过恢复的条件。

云同步下载或合并改变词库后，云端基线版本与完整词库必须作为同一持久化完成条件处理。实现可以同时写 localStorage 与 IndexedDB，但在至少一层确认保存了“最新词库 + 最新基线”的一致快照前，不得显示同步成功。更新基线后触发的 IndexedDB 写入必须被同步流程等待，不能以后台队列尚未完成的状态提前返回成功。

上述严格超集判定用于修复旧版本已经产生的不一致状态：旧 localStorage 可能保留较小词库却被单独写入较新云端基线。删除墓碑仍优先排除用户主动删除的词条，避免恢复时复活已删除内容。

## 验证

- 静态契约检查两端均具备快照指纹、启动摘要和新旧判定逻辑。
- Selenium 模拟 localStorage 保留旧词库且拒绝最新大词库写入，确认重开后仍从 IndexedDB 恢复完整的新词库。
- Selenium 模拟云同步先持久化大词库、后更新云端基线并立即重开，确认成功提示前 IndexedDB 已包含同一最新基线，且历史“旧词库 + 新基线”状态仍可恢复。
- KR 与 JP 使用相同判定和恢复流程，并运行完整质量门禁。
