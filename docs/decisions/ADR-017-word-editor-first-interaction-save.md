# ADR-017：词条编辑器第一次交互直接保存

- 状态：Accepted
- 日期：2026-10-23

## 背景

完整新增/编辑词条弹窗过去只在保存按钮的 `click` 事件中调用 `saveWordFromForm()`。部分输入法或移动端浏览器会把用户第一次点击用于结束输入组合或让当前输入框失焦，导致保存 `click` 未执行，用户必须先点输入框外部或第二次点击保存。JP 的韩文释义 `krMeaning` 尤其容易在持续输入后暴露此问题。

## 决策

1. 保存按钮的鼠标和触屏主入口改为 `pointerdown`：先主动让当前表单输入控件失焦，再立即从 DOM 读取完整草稿并进入既有 `saveWordFromForm()` 原子保存流程。
2. 用户无需预先点击弹窗空白处，也不需要第二次点击保存；当前字段的可见输入值必须包含在本次保存中。
3. 同一次指针激活随后生成的合成 `click` 由短生命周期守卫忽略，防止新增词条重复创建或编辑事务重复执行。
4. 键盘激活和测试脚本调用 `.click()` 时没有先行 `pointerdown`，继续由独立 `click` 入口调用同一提交函数。
5. 保存进行中设置独立 in-flight 守卫并禁用按钮；直到持久化判定结束前，后续指针或键盘激活都不得开始第二次保存事务。
6. `saveWordFromForm()` 先同步验证 localStorage；失败时等待本次排队的 IndexedDB 快照。任一层成功后才关闭弹窗；两层都失败时恢复保存前内存词库与待同步状态，并保留表单草稿。
7. KR/JP 两端使用相同的事件绑定和提交函数；JP 仅在字段集合中额外读取 `inputKrMeaning`。

## 验证

- 静态契约检查双端都存在 `pointerdown`、独立 `click` 兜底、当前焦点 `blur()`、同次激活去重守卫和统一提交函数。
- Selenium 在 KR/JP 弹窗中让最后编辑字段保持焦点，只派发一次 `pointerdown`（不派发 `click`），验证最新值立即进入保存流程、弹窗关闭且只新增一次。
- Selenium 模拟 localStorage 拒绝写入但 IndexedDB 成功，验证等待备用事务后完成；模拟两层都失败时验证回滚、草稿保留与单次错误提示。
- 既有浏览器测试继续覆盖脚本 `.click()`、校验失败及正常保存流程。
