# ADR-018：词库 Excel 严格回导与版本回滚

- 状态：Accepted
- 日期：2026-10-23

## 背景

用户需要把本应用导出的 Excel 在外部编辑后重新导入，并用表格中的差异覆盖既有卡片。Excel 的可见标题承担字段契约；标题被修改时无法安全判断列语义。单词本还需要支持修改词条名称，因此仅按可见单词匹配不足以稳定定位原卡片。

## 决策

1. Header 在 `#exportExcelBtn` 左侧新增 `#importExcelBtn`，点击后打开只接受 `.xlsx` 的隐藏文件输入；KR/JP 的 DOM 与交互镜像一致。
2. 所有可见列标题必须来自当前语言的八列导出标题且保持固定相对顺序。标题改名、重复、未知或乱序时整批拒绝，不允许猜测映射。
3. 新导出文件在可见列末尾附加隐藏 `__EVIE_WORD_ID__` 列。导入优先按该稳定 ID 定位，因此允许用户修改单词值，也允许自定义导出时取消单词列；旧文件没有该列时必须以“单词”为第一列并仅按唯一单词名兼容匹配。导入不创建新词，也不因缺行删除词。
4. 只覆盖文件中实际存在的列。例句列只控制第一组，后续组保留；相近词汇按逐行“单词：中文释义”解析为人工双向关系，并在两侧同时出现在文件时拒绝矛盾声明。
5. 全部校验与差异计算必须在内存副本完成。存在差异时先写入“Excel 导入”本地版本快照，再一次性替换内存词库、生成逐字段时间戳与待上传队列，并等待 localStorage 或 IndexedDB 确认。任一阶段失败均不得留下部分导入。
6. 导入快照显示在云朵入口的版本历史中并共用最近 2 份上限。由于导入本身不读取或改写云端，该快照只允许恢复本浏览器，禁止恢复云端。
7. XLSX 读取支持本应用生成的未压缩 ZIP，以及 Excel/WPS 重存后常见的 Deflate ZIP、inline string 与 shared strings；设置文件与解压体积上限，拒绝异常压缩包和非工作簿内容。

## 验证

- 静态契约检查 Header 顺序、文件类型、严格表头、隐藏 ID、导入前快照、双层持久化和回滚标记。
- Selenium 使用真实导出 Blob 回导，验证字段覆盖、改词名仍按 ID 命中、未导出字段保留、第一例句替换、后续例句保留、相近关系双向、待上传字段、历史快照及仅本地恢复。
- 分别篡改表头、制造未知 ID、重复行和矛盾关系，确认词库、待办与历史均不变化。
- KR/JP 完成同一套断言，并运行完整质量门禁。
