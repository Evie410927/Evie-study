# ADR-020：词条标题旁的复制控件

- 状态：Accepted
- 日期：2026-10-28

## 背景

用户经常需要把词条本身复制到聊天、搜索或笔记中。现有列表卡片和详情弹窗都只能通过长按或拖选文本完成复制，移动端操作成本高，并且卡片主体点击会打开详情，容易与文本选择冲突。

## 决策

1. KR/JP 的列表卡片标题与详情弹窗标题都在词条文字右侧放置同一款紧凑图标按钮；控件固定为 `18 × 18px`、图标字号为 `12px`，列表标题间距为 `6px`、详情标题间距为 `5px`，避免抢占词条视觉焦点。按钮只复制 `word` 字段，不拼接读音、释义、韩文对应表达或其他字段。
2. 点击、触摸复制按钮必须隔离卡片及弹窗的父级点击事件，不得意外打开、关闭或切换详情。
3. 优先使用 `navigator.clipboard.writeText`；该 API 不存在或因 `file://`、权限等原因失败时，使用临时只读文本域和 `document.execCommand('copy')` 兼容复制，结束后立即移除临时节点。
4. 成功后按钮原位短暂显示勾号并出现轻量提示，随后恢复复制图标；失败时明确提示用户手动复制。反馈不得写入词库、持久化介质或云同步队列。
5. 控件必须有中文 `aria-label` 和 `title`，支持键盘激活，并在窄屏标题区域保持自身可见、允许过长词条文字省略。

## 影响

- 不改变词条数据结构、存储或云同步协议。
- 列表和详情新增一致的 DOM/CSS/交互契约。
- 自动化测试同时覆盖 KR/JP 的结构、剪贴板兼容回退、成功反馈和父级点击隔离。
