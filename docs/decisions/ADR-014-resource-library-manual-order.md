# ADR-014：学习资料手动排序

- 状态：Accepted
- 日期：2026-10-19

## 背景

学习资料库当前每次读取都按 `addedAt` 倒序排列，用户无法把经常使用或属于同一学习主题的文件放到相邻位置。只移动 DOM 会在重新打开弹窗、切换 KR/JP 页面或重新载入后丢失；复用文件内容的 `updatedAt` 又会让纯排序被误判为需要重新上传 Blob。

## 决策

1. 每条资料记录增加 `sortOrder`、`orderUpdatedAt` 和仅本地使用的 `orderDirty`。列表按 `sortOrder` 升序、`addedAt` 倒序和稳定 ID 依次比较。
2. 卡片操作区增加独立拖动手柄。手柄支持鼠标与触屏 Pointer Events；键盘聚焦后使用方向键、Home 和 End 完成同等移动。拖动不触发文件打开、下载或删除。
3. 每次移动都把当前可见资料重新编号为连续顺序，并在一个 IndexedDB 事务内写入全部记录。事务成功后才更新内存、重新渲染并提示成功；失败时恢复原顺序。
4. 新增文件放在列表顶部。旧记录首次装载时按原先的新增时间倒序生成稳定顺序，写回 IndexedDB 并进入排序元数据待同步状态。
5. 云端 `resource_files` 增加 `sort_order` 和 `order_updated_at`。排序冲突逐条采用较新的 `order_updated_at`，并与文件内容 `updated_at` 分开比较；只改变顺序时只 Upsert 元数据，不重新上传 Storage Blob。
6. 前端探测到旧云表不支持新增列时，自动回退到旧字段读取和写入，继续完成文件内容同步，同时保留本地 `orderDirty`。数据库升级后下一次同步再补传顺序。
7. KR/JP 使用同一物理 IndexedDB 与元数据表，但依据 ADR-015 按 `language` 分区；排序只在当前语言内部持久化与跨设备同步。DOM、样式、交互和测试继续完全镜像。

## 验证

- 静态契约检查双端均包含拖动手柄、Pointer 生命周期、键盘兜底、原子顺序持久化、独立排序版本和旧云表回退。
- Selenium 在双端新增多份资料，通过键盘移动触发与拖动相同的持久化入口，重新读取 IndexedDB 后顺序保持一致。
- 云同步测试验证排序 Upsert 不上传 Blob、新旧排序时间正确合并，并确认旧 schema 回退不会清除本地待同步顺序。
- 运行完整质量门禁并在部署后确认线上 KR/JP 页面都包含资料排序入口。
