# ADR-009：Tag 筛选采用与词性筛选一致的重置结构

- 状态：Accepted
- 日期：2026-10-09

## 背景

词性筛选已经同时提供下拉底部重置和收起状态快捷重置，而 Tag 筛选仍把已选项额外渲染为搜索框下方的芯片和“清空全部”按钮。两套多选筛选的操作模型不一致，额外摘要栏也占用列表顶部空间。

## 决策

1. 在 `#tagDropdownMenu` 底部增加 `#tagDropdownResetBtn`，紧随可滚动的 `#tagDropdownList`，文案为“重置（显示全部）”。
2. 在 `#tagDropdownBtn` 右侧增加 `#tagQuickResetBtn`；仅当已选 Tag 数量大于 0 时显示，数量归零时隐藏。
3. 两个入口统一调用 `clearAllTagFilters()`，清空 `selectedTags`、回到第一页并立即刷新列表、Badge、快捷按钮和下拉勾选状态。
4. `#activeTagsBar` 保留为空安全兼容节点，但始终清空并隐藏；不得再在搜索框下方渲染已选 Tag 芯片或“清空全部”按钮。
5. 重置只作用于 Tag 筛选，不清空搜索词、主状态或词性筛选。
6. KR/JP 使用完全相同的 DOM ID、CSS、运行逻辑和测试断言。

## 验证

- 契约检查确认底部按钮、快捷按钮的层级、相邻位置、初始隐藏状态和重置绑定。
- 静态测试确认双端不再向 `#activeTagsBar` 写入已选 Tag 摘要。
- 真实浏览器测试选中 Tag 后收起下拉，验证快捷按钮可见、搜索框下方无摘要；点击后验证 Tag 集合、Badge、按钮显隐、页码、勾选状态和结果全部恢复。
- 完整质量门禁继续覆盖 KR/JP 双端和移动端浮层高度。
