# 词性筛选一键重置变更影响分析

## 问题与完成标准

- 问题：词性多选后没有可见的一键重置入口，只能逐项取消。
- 用户可观察结果：词性下拉框底部固定显示“重置（显示全部）”，点击后立即恢复所有词性结果。
- 明确不在范围内：不清空搜索、学习状态、自定义 Tag 或排序，不修改词条数据。
- 完成标准：KR/JP 双端按钮、布局和行为镜像一致；静态契约、真实浏览器回归和完整质量门禁全部通过。

## 影响范围

- [x] KR 应用
- [x] JP 应用
- [ ] 数据字段或缓存迁移
- [ ] localStorage / IndexedDB
- [ ] 云端 payload / RLS / 版本协议
- [x] 列表 / 详情 / 复习 / 相近表达（仅列表筛选）
- [x] 移动端与空状态
- [x] 现有规则或 ADR

## 风险与回滚

- 数据兼容风险：无；仅清空内存中的词性筛选集合。
- 并发或跨设备风险：无；筛选状态不参与持久化或云同步。
- 安全与隐私风险：无。
- 回滚方法：回退双端按钮/CSS、测试、ADR 与质量契约的同一提交。

## 验证计划

- 新增或更新的测试：双端静态 DOM/样式断言；Selenium 多选后点击重置，验证集合、Badge、勾选状态、页码与完整结果。
- 必须运行的质量门禁：`python scripts/run_quality_gate.py`
- 部署后验证：确认 GitHub Pages 的 KR/JP 页面均包含重置按钮及绑定逻辑。
