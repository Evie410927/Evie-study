# 变更影响分析：列表卡片原位记忆备注

## 问题与完成标准

- 问题：`userNote` 只能通过完整编辑弹窗维护，浏览词表时记录和删除个人记忆方式步骤过多。
- 用户可观察结果：红色读音右侧出现小 `＋`；点击后在当前卡片内直接输入并保存；已有备注末尾出现小 `×`，点击即可删除。
- 明确不在范围内：不新增备注字段；不改变详情、复习和相近表达的只读展示；不改变主搜索范围。
- 完成标准：KR/JP 双端均可原位新增、修改、删除，重绘和重开后保持，内部控件不误开卡片详情，修改进入现有云同步待上传队列。

- [x] KR 应用
- [x] JP 应用

- [x] 列表 / 详情 / 复习 / 相近表达
- [x] 移动端与空状态
- [x] 现有规则或 ADR

## 风险与回滚

- 数据兼容风险：无新字段；旧 `userNote` 原样显示并可直接修改或删除。
- 并发或跨设备风险：原位编辑按单字段更新时间参与既有云端冲突合并。
- 安全与隐私风险：输入继续经过 HTML 转义；不写入页面属性或执行脚本。
- 回滚方法：移除列表卡片 `＋`、原位输入和 `×` 控件，保留 `userNote` 数据及完整编辑弹窗入口。

## 验证计划

- 新增或更新的测试：控件紧邻读音、空备注原位新增、已有备注预填修改、Enter/失焦保存、Escape 取消、`×` 删除、事件隔离、持久化与云同步待处理字段。
- 必须运行的质量门禁：`python scripts/run_quality_gate.py`
- 部署后验证：确认 GitHub Pages KR/JP 均包含 `startWordCardUserNoteEdit`、`saveWordCardUserNote` 与 `deleteWordCardUserNote`。
