# 变更影响分析：学习资料库按语言隔离

## 问题与完成标准

- 问题：JP 上传的学习资料会出现在 KR，因为本地与云端资料模型都没有语言维度。
- 用户可观察结果：KR 只显示 KR 资料，JP 只显示 JP 资料；现有无语言资料归入 JP。
- 明确不在范围内：不搬移或重传既有 Storage Blob，不改变词库数据与词库云同步。
- 完成标准：本地、云端元数据、删除墓碑和排序均按语言隔离，双端自动化与质量门禁通过。

- [x] 现有规则或 ADR

## 风险与回滚

- 数据兼容风险：无语言记录必须确定归属；依据用户报告统一归入 JP，且不删除 Blob。
- 并发或跨设备风险：未升级云表的设备不得继续使用无语言协议，以免重新串库。
- 安全与隐私风险：语言过滤是用户行级隔离之上的第二层逻辑边界；查询和写入都必须带语言。
- 回滚方法：回滚前端与 SQL 变更会恢复共享列表，但不会删除已加语言的本地或云端资料。

## 验证计划

- 新增或更新的测试：双端静态语言分区契约、IndexedDB 旧记录迁移与外语记录隐藏、上传语言字段、云同步 payload 和 SQL 迁移断言。
- 必须运行的质量门禁：`python scripts/run_quality_gate.py`
- 部署后验证：确认远端提交与 KR/JP GitHub Pages 均包含各自 `RESOURCE_LANGUAGE` 和语言过滤实现。
