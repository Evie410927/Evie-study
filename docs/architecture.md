# 单词本应用架构

## 目标

本项目交付两个可直接打开和部署的单文件应用：韩语单词本与日语单词本。两端共享相同的页面结构、交互和存储协议，仅保留质量契约明确允许的语言差异。

## 系统边界

```text
用户交互
  -> KR / JP 单文件应用
     -> 内存状态 this.words
     -> SafeStorage
        -> localStorage
        -> IndexedDB 持久化降级
     -> Supabase Auth
     -> vocab_items + 同步版本元数据

质量控制
  -> config/quality-contract.json
  -> scripts/validate_project_contract.py
  -> test_vocab_apps.py
  -> GitHub Actions / 本地质量门禁
```

## 主要职责

| 模块 | 职责 | 修改时必须检查 |
|---|---|---|
| `standalone_kr_vocab.html` | 韩语数据和完整应用运行时 | JP 镜像、存储迁移、浏览器回归 |
| `standalone_jp_vocab.html` | 日语数据和完整应用运行时 | KR 镜像、`krMeaning` 特例、浏览器回归 |
| `supabase_vocab_sync.sql` | 云端数据结构、主键和 RLS | 前端 payload、认证、分页和版本协议 |
| `test_vocab_apps.py` | 静态契约及真实浏览器回归 | 两端对称覆盖、测试隔离和可重复性 |
| `AGENTS.md`、`rules/` | AI 行为、语言学习与交付流程 | 不得与质量契约和已接受 ADR 冲突 |

## 架构原则

1. `config/quality-contract.json` 是可执行质量约束的唯一数据源。
2. 架构变化必须新增或更新 ADR，同时更新契约与自动化测试。
3. 用户数据修改必须经过持久化成功确认后才能显示成功反馈。
4. 云端版本变化、删除和本地待上传修改必须通过明确的冲突协议处理。
5. 保持单文件离线交付能力；共享模块拆分应先提供可靠构建与内联产物流程，不能直接破坏 standalone 交付。
6. 页面启动必须比较 localStorage 与 IndexedDB 的有效快照；旧但非空的 localStorage 不得阻止更新的 IndexedDB 快照恢复。
   云同步改变词库与云端基线时，成功反馈必须等待至少一层存储确认保存二者的一致快照；在缺少可信保存时间的历史数据上，墓碑感知的 IndexedDB 严格超集恢复优先于可能被单独提前写入的云端基线。
7. 相近表达的展示顺序由每个源词条自己的 `manualSimilarWordIds` 数组顺序决定；详情与复习视图直接拖动卡片后立即持久化该顺序，新增/编辑词条弹窗中的已选相近词卡片也允许直接拖动，但只更新 `editingModalSimilarWordIds` 草稿顺序，必须等用户明确保存词条后才写入 `manualSimilarWordIds`。三处均不新增拖拽按钮，也不改变反向词条的独立排列；关闭编辑弹窗须放弃未保存的草稿排序。
8. 红色读音右侧的发音/记忆提示使用独立字段 `pronunciationNote`；下方中括号内容说明继续使用 `userNote`。两字段不得互相回填、覆盖或删除。列表卡片第一排只承载词条标题、JP 专属 `krMeaning` Badge 与右侧状态/星级；红色读音、`＋`、黄色备注和 `×` 整体放到标题下方、词性释义上方的独立第二排，并横跨卡片正文全宽。进入列表发音备注编辑态时，红色读音、`＋` 与输入框必须使用底边对齐，编辑框从读音后弹性延伸至卡片右边缘，不再受状态、星级或 JP Badge 挤压。详情弹窗同样把红色读音和发音备注组件放到标题下方、词性与释义上方的独立第二行，并让该行横跨弹窗正文全宽。列表与详情中的 `＋` 均不得使用负左边距，必须与读音保留清晰间隔，不能产生遮挡或粘连观感。详情弹窗无返回历史时，词条标题、第二行读音、词性标签与内容说明共用同一条可见左边线；从相近表达进入而显示返回箭头时，第二行读音及发音备注必须增加与“返回按钮宽度＋标题间距”相同的缩进，继续与上方词条正文左边线对齐，返回箭头消失时自动恢复。词性释义行不得再增加背景卡片、左侧强调边或左内边距。点击 `＋` 以空白输入追加内容，点击已有发音备注则回填全文并原位替换编辑，末尾 `×` 直接删除；`＋`、已有备注和删除控件在 `pointerdown` 阶段都只能隔离事件、不得改变 DOM，必须等 `click` 明确命中控件后才执行新建、编辑或删除，防止移动端合成点击穿透并打开卡片详情。原位编辑文本按可用宽度自动换行并随内容增高，不显示横向或纵向滚动条，也不得由滚动条遮挡文字。完整新增/编辑词条弹窗还必须在“发音 / 罗马音标注”之后、“中文释义”之前提供独立的“发音备注”字段，新建时为空、编辑时回填现值，保存时替换 `pronunciationNote` 而不得清空或改写 `userNote`；该字段产生非空输入时，下方卡片标签草稿必须在同一次 `input` 事件中立即显示 `发音` Tag，但不得在用户保存整张词条前提前改写词库、localStorage 或云同步队列。黄色备注不得设置固定像素宽度上限，只在独立发音行的真实可用空间不足时省略，末尾删除控件始终保留。任一入口保存或删除后必须立即刷新列表与详情视图。两字段分别参与本地持久化与逐字段云同步。非空 `pronunciationNote` 必须自动带有自定义 Tag `发音`：新建或修改备注时同时更新 `tags`，旧本地数据、IndexedDB 备用快照、导入和云端合并数据在归一化时全量补齐并排队同步；删除备注不自动删除 `发音` Tag，避免误删用户分类。
9. 详情弹窗的标题操作区、独立发音行、词性释义、内容备注及 Tag/`+` 组成固定顶部区域，不参与正文滚动；独立滚动容器 `.detail-scroll-content` 必须从例句区域开始，并包含例句与下方相近表达。详情外层与 `.detail-body` 不得产生第二条纵向滚动条；重新打开、切换相近词、从编辑器返回以及拖拽自动滚动时，都必须读取或操作该独立滚动容器。详情弹窗自底部贴合并使用 `92dvh` 高度（以 `92vh` 兼容回退），把顶部留白压缩至约视口的 8%，同时保留移动端安全间距和底部操作栏。
10. 完整新增/编辑词条弹窗中的发音备注使用与读音字段等高的单行文本输入框，不使用多行文本域。词条、中文释义与词性是且仅是该表单的三个必填项：三者必须同时使用 `required-field` 分组、可见的“必填”胶囊和柔和玫红虚线边框，聚焦时切换为实线高亮；读音、发音备注、说明、例句、Tag、星级、状态及相近表达等可选项不得套用必填样式。
11. 列表卡片的纵向空间优先服务阅读内容：词性释义与非空单词说明之间保留 8px，单词说明与例句之间保留 10px。低频 Tag/操作底栏仍完整保留自定义 Tag、`+`、发音、编辑和删除，但采用 6px 上间距、4px 上内距及 18–22px 的紧凑控件高度，不得用大块空白挤压正文。
12. 新建词条弹窗每次展开完整“单词词性”候选列表时，都必须把候选容器的横向与纵向滚动位置重置到起点；重置需在取消 `hidden` 后立即执行，并在下一布局帧再次校正，防止移动端浏览器复用上一次下拉滚动位置。输入文字后的筛选列表仍保持实时交互，编辑既有词条时不得清空已回填的词性值。
13. 列表页词性多选下拉框底部固定提供“重置（显示全部）”按钮。按钮必须位于可滚动词性列表之后、独立于滚动区域；同时，当已选词性数量大于 0 时，收起状态下必须在词性触发按钮右侧显示独立快捷重置按钮，数量归零后自动隐藏。任一入口点击后都清空全部词性选择、回到第一页并立即刷新列表、Badge、快捷按钮与勾选状态，使所有词性重新参与显示。KR/JP 两端的 DOM、样式、行为和测试保持镜像一致。
14. 列表页 Tag 多选筛选必须与词性筛选使用相同的双重重置结构：下拉列表底部固定提供“重置（显示全部）”，已选数量大于 0 时在 Tag 图标触发按钮右侧显示独立快捷重置按钮，数量归零后自动隐藏。已选 Tag 不再以芯片或“清空全部”按钮单独占用搜索框下方区域；选中状态只通过下拉勾选、按钮数字和快捷重置入口表达。KR/JP 两端保持镜像一致。
15. 列表分页的“每页”选择器固定提供 10、20、50 三档，并以 50 条作为静态选中值、应用运行时初始值和非法输入回退值。KR/JP 两端必须一致，避免控件显示值与实际切片数量不一致。
16. 详情弹窗与复习背面的相近表达卡片必须在读音标注右侧紧邻显示非空 `pronunciationNote`，使用与主卡片发音备注一致的杏黄色层级；词条、读音与发音备注必须使用统一的 `1.25` 行高并按文字基线对齐，使不同字号的文字下沿形成稳定、舒适的一条视觉线。相近表达中的备注仅展示，不提供编辑、追加或删除控件。空备注不渲染节点，所有内容必须经 HTML 转义，KR/JP 两端镜像一致。
17. 顶部资料库是与词条数据隔离的附件子系统。KR/JP 在同源环境下共用物理 IndexedDB `evie_vocab_resource_library_v1`，但 `files` 与 `deletions` 的每条记录必须带 `language`，页面只读取当前语言分区；旧版无语言记录确定迁移为 JP。文件不得进入 `this.words`、词库 localStorage、词库 JSON/HTML 导出或 `vocab_items`。云同步使用私有 Supabase Storage bucket `vocab-resources` 保存原始 Blob，并使用独立 `resource_files` 表保存语言、名称、类型、大小、SHA-256、对象路径、更新时间与删除墓碑；两者均按登录用户执行 RLS，元数据再按 `language` 隔离。新对象路径为 `user_id/language/resource_id/resource_id.extension`，旧 JP 路径保持引用而不破坏性搬移。云朵弹窗必须提供独立“同步学习资料”选项。同步时只交换当前语言的元数据和待上传文件，不自动下载全部远端 Blob；云端独有资料只创建元数据卡片，用户点击时才下载并写入当前语言缓存。每张资料卡片在下载按钮左侧提供页内重命名入口，只允许修改文件主名称并固定保留原扩展名；保存前校验空名、文件系统非法字符和当前语言重名，IndexedDB 事务成功后才刷新。改名以 `metadataDirty` 独立进入资料同步待办，只更新 `resource_files` 元数据，不重复上传 Blob，也不改变稳定 ID、Storage 路径、类型、大小或哈希。常见位图必须在当前页面的资料图片预览层中显示，关闭预览后仍停留在资料列表，不得新开浏览器标签页；非图片继续使用浏览器或系统的原生打开/下载能力。删除必须先成功写入当前语言元数据墓碑，再通过 Storage API 删除对象，防止旧设备复活文件。上传必须显示进度、保留失败待办并提供有限重试；任何云端失败不得删除本地 Blob 或冒充同步成功。云表缺少 `language` 时必须停止资料同步并提示升级，不能回退为读取共享数据。
18. 每次词库云同步在改变任一侧之前，必须把同步前的本地完整状态与刚读取的云端完整状态合并保存为独立 IndexedDB 历史快照，最近只保留 2 份；读取旧版历史时同步裁剪并持久化最近 2 份。弹窗提供“撤销上次同步”和“同步历史”；用户可只恢复当前浏览器，也可把本地与云端分别恢复到各自的同步前状态。云端恢复必须为恢复结果创建更高的新 revision，并为快照外的当前云端词写墓碑，不得倒退 revision 或把历史快照本身删除。历史落盘失败时停止词库同步；纯学习资料同步不创建词库撤销快照。
19. 学习资料卡片顺序由当前语言分区内每条资料的 `sortOrder` 升序决定。拖动手柄统一支持鼠标 Pointer、触屏 Pointer 和键盘方向键；完成排序后必须先把当前语言整组新顺序、统一的 `orderUpdatedAt` 和 `orderDirty` 原子写入资料 IndexedDB，再刷新并提示成功。资料顺序与 Blob 内容版本相互独立，云端通过当前语言的 `resource_files.sort_order`、`order_updated_at` 按最新排序时间合并，不能因为排序而重新上传 Blob。旧云表没有排序列时，前端回退到旧排序元数据协议并保留本地 `orderDirty`，不得让排序升级阻断文件同步。
20. Header 的 Excel 导出入口位于新增词条按钮左侧，资料库按钮再位于导出入口左侧。导出弹窗以互斥范围选择控制全部、学习中、已掌握、Tag 多选（任一匹配）或无星至五星多选（精确任一匹配），浏览器在本地直接封装 Open XML `.xlsx`，不引入联网依赖。工作表只读当前内存词库快照，统一展示单词、词性、释义、例句、发音、发音备注、说明、相近词汇八个列复选框；前四列默认勾选，后四列默认关闭，用户可取消或追加任一列，但零列时必须阻止导出。表头为带主题色填充的粗体，列坐标、宽度和筛选范围随选择动态生成，数据单元格换行显示。JP 的中文释义与韩文对应表达在释义单元格分行，例句只取第一组现存原文和中文翻译。相近词汇只读人工关系，并在同一单元格按人工顺序逐行输出“单词：中文释义”，不得携带关联词的其他字段，JP 也不得追加韩文表达。保存位置不显示开关：支持 File System Access API 时自动打开系统“另存为”，取消不下载；不支持时直接使用浏览器默认下载且不显示兼容性提示。生成与下载不能写回词库、持久化介质或云同步状态。
21. 完整新增/编辑词条弹窗的保存按钮必须在第一次鼠标或触屏 `pointerdown` 时先抓取仍保持焦点的完整表单草稿，再主动结束当前输入控件的焦点状态，等待一个布局帧让移动端输入法组合、`input` 与 `focusout` 完成，并重新抓取稳定草稿后进入 `saveWordFromForm()` 原子保存流程；等待期间控件失联时使用失焦前草稿兜底。草稿必须覆盖全部 input、textarea、JP 专属 `krMeaning` 及动态例句原文/翻译，不能要求用户先点击输入框外部。随后产生的同一次合成 `click` 必须被短时守卫去重，避免重复新增或重复写入；键盘激活及脚本 `.click()` 仍通过 `click` 兜底保存。保存进行中必须禁用按钮并忽略重复激活。持久化先验证 localStorage；若手机浏览器拒绝该层写入，必须等待本次已排队的 IndexedDB 快照事务，任一层确认成功即可完成，不能在 IndexedDB 尚未返回时误报失败。两层都失败时须回滚本次内存词库及待同步状态、保留弹窗与表单草稿，并只显示一次失败提示。KR/JP 两端使用完全相同的提交入口；JP 的 `krMeaning` 只作为允许的字段差异。
22. Header 的 Excel 导入入口固定放在 Excel 导出入口左侧。导入只接受本应用导出的 `.xlsx`：可见首行表头必须使用当前语言的标准标题并保持标准相对顺序；KR 使用八个可选列，JP 将释义拆成独立的“中文释义”与“韩文释义”后使用九个可选列，分别映射 `meaning` 与 `krMeaning`，不得再用同一单元格换行混合。任一标题被改名、重复、乱序或出现未知列时，必须在改写词库前整体拒绝。新版导出在工作表末尾写入隐藏的稳定词条 ID 列，因此即使用户自定义导出时取消“单词”列也能按 ID 安全覆盖；没有隐藏 ID 的旧导出文件才必须以“单词”为第一列并按唯一单词名兼容匹配。导入只更新文件中实际出现的词条及列，未出现的词条和未导出的字段保持不变；第一组例句可替换或清空，后续例句保持，相近词关系按人工双向关系校验更新。任何未知、重复、跨语言或相近关系冲突均整批拒绝，不允许部分写入。确认存在差异后，必须先在云朵入口共用的版本历史中保存“Excel 导入”前本地快照；快照失败则中止，保存失败则回滚词库、待同步状态和刚创建的历史。成功反馈必须等待 localStorage 或 IndexedDB 至少一层确认，所有差异进入逐字段待上传队列。仅记录本地状态的导入快照允许恢复本浏览器，但不得冒充已捕获云端状态执行云端恢复。

## 变更影响路径

```text
字段变化
  -> 新增/编辑表单
  -> 内存模型
  -> 本地持久化
  -> 云端 payload
  -> 缓存迁移
  -> 列表/详情/复习/相近表达视图
  -> KR/JP 对称测试

布局或交互变化
  -> DOM 契约
  -> CSS 与事件绑定
  -> 空状态和移动端
  -> Selenium 回归
```
