# 学习资料手动排序变更影响分析

## 问题与完成标准

- 问题：资料文件固定按新增时间倒序显示，无法按学习需要重排；仅调整 DOM 会在重开或换页面后丢失。
- 用户可观察结果：每张资料卡片显示拖动手柄，电脑可拖动，手机可按住拖动，键盘可上下移动；关闭并重新打开后顺序不变。
- 明确不在范围内：不增加文件夹、批量选择、自动分类或词库卡片排序规则。
- 完成标准：KR/JP 镜像；顺序原子落盘；跨页面共享；云端排序不重复上传 Blob；旧云表回退安全；测试与质量门禁通过。

## 影响范围

- [x] KR 应用
- [x] JP 应用
- [x] 数据字段或缓存迁移
- [x] localStorage / IndexedDB

- [x] 移动端与空状态
- [x] 现有规则或 ADR

## 风险与回滚

- 数据兼容风险：旧记录没有顺序字段；首次加载按原新增时间生成顺序并在一个事务内写回，不改 Blob 和稳定 ID。
- 并发或跨设备风险：排序使用独立更新时间进行最新值合并；中途失败保留本地待同步标记，纯排序不覆盖文件内容。
- 安全与隐私风险：只增加整数顺序和时间戳，不新增文件内容、账号信息或公开权限。
- 回滚方法：移除拖动入口和云端排序字段读取，旧前端会忽略 IndexedDB/数据库中的附加字段，文件仍按新增时间显示。

## 验证计划

- 新增或更新的测试：双端静态契约、手柄与 Pointer/键盘交互、IndexedDB 重载持久化、排序云同步、Blob 不重传、旧 schema 回退和 SQL 字段检查。
- 必须运行的质量门禁：`python scripts/run_quality_gate.py`
- 部署后验证：远端提交与 GitHub Pages 的 KR/JP 页面均包含 `resource-file-drag-handle`、`startResourceFileSort` 和排序持久化逻辑。
