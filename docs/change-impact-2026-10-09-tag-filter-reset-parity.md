# Tag 筛选重置结构一致化变更影响分析

## 问题与完成标准

- 问题：Tag 筛选与词性筛选的重置入口不一致，且已选 Tag 摘要单独占用搜索框下方空间。
- 用户可观察结果：Tag 下拉底部和 Tag 图标右侧分别提供重置入口；搜索框下方不再显示 Tag 芯片与“清空全部”。
- 明确不在范围内：不修改卡片自定义 Tag、Tag 数据、搜索、主状态或词性筛选结果。
- 完成标准：KR/JP 双端 DOM、样式和行为镜像；静态契约、真实浏览器回归和完整质量门禁全部通过。

## 影响范围

- [x] KR 应用
- [x] JP 应用
- [ ] 数据字段或缓存迁移
- [ ] localStorage / IndexedDB
- [ ] 云端 payload / RLS / 版本协议
- [x] 列表 / 详情 / 复习 / 相近表达（仅列表 Tag 筛选）
- [x] 移动端与空状态
- [x] 现有规则或 ADR

## 风险与回滚

- 数据兼容风险：无；只改变内存筛选状态的入口和展示位置。
- 并发或跨设备风险：无；筛选状态不参与持久化或云同步。
- 安全与隐私风险：无。
- 回滚方法：回退双端 Tag 重置 DOM/CSS/显隐逻辑、测试、ADR 与质量契约的同一提交。

## 验证计划

- 新增或更新的测试：双端静态 DOM/样式/隐藏摘要断言；Selenium 在收起状态点击快捷重置，并验证底部重置入口、集合、Badge、勾选、页码和搜索下方零摘要。
- 必须运行的质量门禁：`python scripts/run_quality_gate.py`
- 部署后验证：确认 GitHub Pages 的 KR/JP 页面均包含 Tag 双重重置入口和隐藏摘要逻辑。
