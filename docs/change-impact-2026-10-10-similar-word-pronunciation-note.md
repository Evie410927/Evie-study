# 相近表达发音备注展示变更影响分析

## 问题与完成标准

- 问题：相近表达卡片未展示关联词已有的发音备注。
- 用户可观察结果：详情与复习的相近表达卡片在读音右侧显示非空发音备注。
- 明确不在范围内：不改变发音备注字段、持久化、云同步或相近关系；不在相近卡片内增加编辑控件。
- 完成标准：KR/JP 双端结构与样式一致，空值无占位，特殊字符安全转义，静态与真实浏览器测试通过。

## 影响范围

- [x] KR 应用
- [x] JP 应用
- [ ] 数据字段或缓存迁移
- [ ] localStorage / IndexedDB
- [ ] 云端 payload / RLS / 版本协议
- [x] 列表 / 详情 / 复习 / 相近表达（详情与复习的相近表达区域）
- [x] 移动端与空状态
- [x] 现有规则或 ADR

## 风险与回滚

- 数据兼容风险：无；只读取既有 `pronunciationNote`。
- 布局风险：长备注可能挤压标题；使用可收缩单行省略保护。
- 安全风险：备注必须 HTML 转义，防止用户文本被解释为标记。
- 回滚方法：回退双端相近表达备注节点、CSS、测试、ADR 与契约的同一提交。

## 验证计划

- 新增或更新的测试：双端静态字段/样式/转义断言；Selenium 验证详情与复习相近卡片的备注文字、位置、空值及只读性。
- 必须运行的质量门禁：`python scripts/run_quality_gate.py`
- 部署后验证：确认 GitHub Pages 的 KR/JP 页面均包含 `.similar-word-pronunciation-note` 与备注渲染逻辑。
