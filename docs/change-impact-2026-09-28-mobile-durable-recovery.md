# 变更影响分析：手机端重开后词库回退

## 问题与完成标准

- 问题：手机端云同步后内存中为最新词库，但 localStorage 写入受限时仍残留较小旧词库；重开页面因旧数据非空而跳过 IndexedDB 恢复。
- 用户可观察结果：同步到 2241 词后关闭并重开页面，仍保持最新词库，不再回退到 2065 词。
- 明确不在范围内：不改变云端表结构、账号认证、同步方向选择或词条合并规则。
- 完成标准：KR/JP 启动时均选择更新的有效持久化快照；旧但非空的 localStorage 不阻断 IndexedDB；完整质量门禁通过。

- [x] 移动端与空状态
- [x] 现有规则或 ADR

## 风险与回滚

- 数据兼容风险：旧版本没有快照元数据；使用云端基线、变更时间和墓碑感知的词条集合差异完成首次判定。
- 并发或跨设备风险：恢复仅比较本机两层持久化，不发起自动云同步，不改变手动同步约束。
- 安全与隐私风险：新增元数据仅包含保存时间和本地内容指纹，不包含词条正文或账号信息。
- 回滚方法：回退 ADR-003、质量契约、本次双端恢复逻辑和对应测试；原有 localStorage 与 IndexedDB 数据格式保持兼容。

## 验证计划

- 新增或更新的测试：模拟 localStorage 保留旧词库且拒绝新词库写入，验证 IndexedDB 已落盘并在重开状态下恢复较新完整词库；KR/JP 对称执行。
- 必须运行的质量门禁：`python scripts/run_quality_gate.py`
- 部署后验证：检查 GitHub Pages 两端包含 `shouldRestoreDurableSnapshot` 与 `LOCAL_SNAPSHOT_META_KEY`，并确认页面返回 200。
