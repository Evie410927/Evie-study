# 云同步撤销历史变更影响分析

## 问题与完成标准

- 问题：单向上传或下载一旦误点，会覆盖另一侧状态；现有耐久快照和 revision 都不保留可供用户选择的历史版本。
- 用户可观察结果：云同步弹窗可撤销上次词库同步并查看最近 5 次历史；恢复前展示影响摘要，可选择只恢复浏览器或同时恢复云端。
- 明确不在范围内：学习资料 Blob、`resource_files` 和 Storage 对象不参与词库撤销；不提供跨设备共享的历史中心。
- 完成标准：同步前复合快照持久化失败时阻止词库同步；两种恢复模式均保持快照、正确刷新页面并遵守云端 revision 单调递增。

## 风险与回滚

- 数据兼容风险：历史使用现有耐久 IndexedDB 的独立键，不修改当前快照 schema；旧版本会忽略该键。
- 并发或跨设备风险：云端恢复前重新读取当前状态，对快照外新增词写墓碑，并创建高于当前值的新 revision；已打开的其他设备下次同步按既有协议处理。
- 安全与隐私风险：历史只在当前浏览器 IndexedDB 保存，不跨用户上传；退出账号不会自动删除本机词库历史，与现有本地词库行为一致。
- 回滚方法：回退 ADR、质量契约、双端 UI/运行时和测试；保留未被旧版本读取的 IndexedDB 历史键，避免破坏用户数据。

## 验证计划

- 新增或更新的测试：双端 DOM 对称、历史上限、同步前门禁、仅本地恢复、双端恢复、revision 递增、快照写入失败及资料同步隔离。
- 必须运行的质量门禁：`python scripts/run_quality_gate.py`
- 部署后验证：远端提交与 GitHub Pages 的 KR/JP 页面均包含 `cloudSyncUndoBtn`、`cloudSyncHistoryBtn` 和复合快照方法。
