# 变更影响分析：词条编辑器实时草稿首次保存

## 问题与完成标准

- 问题：说明等输入框在仍保持焦点或输入法组合尚未结束时，第一次点击保存可能只触发失焦，最新内容没有进入保存事务。
- 用户可观察结果：任一输入框或例句文本框输入完成后，无需先点空白处，第一次点击保存即可保存全部最新内容。
- 明确不在范围内：不改变词条字段结构、云同步协议、筛选排序或展示样式。
- 完成标准：KR/JP 均在第一次 `pointerdown` 抓取并稳定提交完整表单草稿，合成 `click` 不重复保存，键盘点击仍可用。

## 风险与回滚

- 数据兼容风险：无；只改变表单值进入既有保存事务的时序。
- 并发或跨设备风险：保存进行中守卫继续阻止第二次事务，不改变云端字段合并。
- 安全与隐私风险：无新增外部传输或权限。
- 回滚方法：回退本次提交，恢复 ADR-017 原来的失焦后立即读取逻辑。

## 验证计划

- 新增或更新的测试：静态检查完整草稿抓取与输入法稳定等待；浏览器测试让说明保持焦点，单次 pointerdown 后核对全部普通字段和例句均保存。
- 必须运行的质量门禁：`python scripts/run_quality_gate.py`
- 部署后验证：确认 GitHub Pages 的 KR/JP 文件均包含 `captureWordFormDraft` 与稳定等待逻辑。
