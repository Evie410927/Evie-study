# 变更影响：词条编辑器第一次点击直接保存

## 问题与完成标准

- 问题：输入框仍有焦点或输入法仍在收尾时，第一次点击保存可能只触发失焦而没有保存，必须再次点击。
- 用户可观察结果：在任意字段完成输入后直接第一次点击保存，即可保存当前可见值并关闭弹窗。
- 明确不在范围内：不改变字段定义、校验规则、云同步协议、弹窗布局或 Enter 防误提交规则。
- 完成标准：KR/JP 首次鼠标/触屏交互直接保存；同次合成 click 不重复保存；键盘/脚本 click 可保存；持久化失败仍保留草稿。

## 影响范围

- [x] KR 应用
- [x] JP 应用
- [ ] 数据字段或缓存迁移
- [x] localStorage / IndexedDB
- [ ] 云端 payload / RLS / 版本协议
- [ ] 列表 / 详情 / 复习 / 相近表达
- [x] 移动端与空状态
- [x] 现有规则或 ADR

## 风险与回滚

- 数据兼容风险：无字段与格式变化；只调整进入既有保存事务的事件时机。
- 并发或跨设备风险：无新增同步行为；同次事件守卫反而避免重复保存。
- 安全与隐私风险：无。
- 回滚方法：移除 `pointerdown` 提交和去重守卫，恢复仅 `click` 保存；会重新暴露首次点击被失焦吞掉的问题。

## 验证计划

- 新增或更新的测试：双端静态事件契约；真实浏览器保持输入焦点并仅派发一次 `pointerdown`，验证最新值、持久化、弹窗关闭与无重复词条；保留既有 `.click()`、校验失败和持久化失败测试。
- 必须运行的质量门禁：`python scripts/run_quality_gate.py`
- 部署后验证：检查 KR/JP GitHub Pages 均包含 `commitWordModalDraftAndSave` 与保存按钮 `pointerdown` 绑定。
